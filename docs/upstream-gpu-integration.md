# Upstream GPU integration

This repository provides a CUDA adapter for an installed 21cmFAST 4.3.2 package. The Python entry points in [v4/gpu_lightcone.py](../v4/gpu_lightcone.py) use native 21cmFAST input, output, lightconer and cache objects. The root `pyproject.toml` installs the v4 dependency set. The adapter is loaded from this repository's `v4/` directory. The root Conda recipe serves the v3 pipeline. For v4 setup and examples, see the [adapter guide](../v4/README.md).

## Upstream review

[Issue #728](https://github.com/21cmfast/21cmFAST/issues/728) tracks GPU support. The maintainers asked to carry the existing work and review forward to the 4.3 release branch. [PR #622](https://github.com/21cmfast/21cmFAST/pull/622) covers initial conditions, MapMass and perturbations. [PR #670](https://github.com/21cmfast/21cmFAST/pull/670) builds on it with device residency, cuFFT and spin-temperature acceleration.

| Review point | Local implementation and evidence |
| --- | --- |
| Same seed defines the same simulation | The adapter has native GSL-compatible draw and IC comparisons. A same-seed run that generates ICs independently checks reproducibility. A shared-IC run checks downstream stages with identical inputs. Record the seed, PRNG and thread count with each comparison. [Upstream RNG review](https://github.com/21cmfast/21cmFAST/pull/622#discussion_r3145955463) · [Local RNG evidence](../reports/v432-multithread-rng.json) |
| Preserve public interfaces | The local adapter exposes `run_coeval`, `generate_coeval`, `run_lightcone` and `generate_lightcone` with native objects. An upstream package integration still needs CPU-only and CUDA build and public API checks. [Entry points](../v4/gpu_lightcone.py) |
| Explain GPU coverage and CPU paths | The adapter checks source model, grid and option coverage before entering CUDA. Unsupported configurations fall back to the native CPU driver with a warning by default. Validation runs set `fallback_to_cpu=False`. CLASS solving, parts of the geometry and photon calibration fitting run on the host. The status index and per-run routing document where work ran. [Mini-halo review](https://github.com/21cmfast/21cmFAST/pull/622#discussion_r3108929451) · [Local status and limitations](21cmFAST-4.3.2-GPU-status.md#未完成或仍有限制) |
| Keep thresholds specific to the affected test | Record absolute errors in physical units alongside relative comparisons, especially near zero brightness. Preserve the upstream assertions when recording comparison results. [Upstream tolerance review](https://github.com/21cmfast/21cmFAST/pull/622#discussion_r3120487140) |
| Put build and profiling guidance in the developer docs | For an upstream submission, put build options and profiling instructions under the Sphinx developer documentation and link them from its index. The review also asks to drop pre-release build aliases and target Python 3.12–3.14. These are upstream integration items. The local v3 Conda recipe has its own dependency pins. [Build documentation review](https://github.com/21cmfast/21cmFAST/pull/622#discussion_r3120124844) · [Legacy aliases review](https://github.com/21cmfast/21cmFAST/pull/622#discussion_r3120127149) · [Python version review](https://github.com/21cmfast/21cmFAST/pull/622#discussion_r3120088632) |

## Validation evidence

- The [4.3.2 status index](21cmFAST-4.3.2-GPU-status.md) links to local field, global-history, power-spectrum, halo and throughput evidence. The [perturbation report](../reports/v432-perturb-algorithms.json) covers first-node linear, Zel’dovich and 2LPT comparisons. The recorded large molecular-cooling case includes 37 near-zero lightcone brightness voxels outside the stated tolerance.
- Keep a per-commit CPU and GPU record for the upstream pytest suite, including the three historical #670 cases: `test_minimize_memory_on_global_evolution[E-INTEGRAL]`, `test_global_quantities[E-INTEGRAL]` and `test_global_quantities[CONST-ION-EFF]`. Record independent coeval and lightcone results with Zel’dovich and 2LPT on each GPU architecture in the #622 test plan. [Base PR test plan](https://github.com/21cmfast/21cmFAST/pull/622) · [Optimization PR regressions](https://github.com/21cmfast/21cmFAST/pull/670)
- For developer profiling, use the matched node, thread count, timing boundary and transfer counters documented in the [4.3.2 adapter guide](../v4/README.md#device-residency-and-zero-upload-lightcones). The [v3 profiling and benchmark record](GPU_vs_CPU_comparison.md) uses its own workload and reference build.
